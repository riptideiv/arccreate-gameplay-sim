# 双臂缠绕约束与真实解缠

默认限制为 **±260°**，工作台「手部动作」可调整为 90–355°。基准是双手待机时，左袖口指向右袖口的连线在平板平面内的方向。使用展开角度而非每帧归一到 ±180°；抬手、回位和跨过角度分支都不会清零。

袖口是模型的手臂连接位置。先完成接触固定的手套姿态求解，再用真实袖口偏移计算缠绕。这样绕触点转腕不能绕过限制，两个指尖接住同一个计分点时也不必把指尖连线误当成手臂连线。

## 轨迹搜索

`winding_paths.py` 在固定触点与腕部姿态的条件下搜索离屏运动：

- 每段离屏时间允许原路、顺时针、逆时针的不同绕行。袖口围绕另一个袖口的有限半径轨迹使用切线／圆弧／切线；近距离端点先退出绕行圆盘。候选还包括不同半径、抬手高度和时间分配。
- 端点和所有按住的采样保持不变。必要的解缠可使用主移动速度预算，旋转引起的表面速度也从预算中扣除；普通待机和可选避让继续受待机速度约束。
- 有向无环图记录帧与整数绕行圈数。同一几何位置的不同缠绕分支分别保留，不能合并丢掉历史。上限小于 360° 时，每帧最多两个有效圈数分支。
- 边只更改一只手的一整段离屏运动；选中的边互不重叠。图在这些有限候选中，按额外路程、舒适速度以上的运动代价和手套间距代价选出可行路径。绕远路有真实代价，限制始终为硬约束。

这使演奏可以在地面长按松开后主动解缠，不需要为了省运动代价而无限缠下去。固定触点搜索、原生判定规则与计分时间不变。

## 连续性与失败处理

每条候选检查完整 60 Hz 路径及采样之间的线段；袖口连线不能穿过原点来偷换绕行分支。最终用与 Blender／WebGL 相同的线性位置和俯仰／偏航插值复核。旋转曲线相对弦的偏差界为 `r*(|Δpitch|+|Δyaw|)^2/8`；对细分段应用该界，验证采样之间也没有越界或隐藏的分支穿越。

解缠在姿态求解之后执行，后面不再添加能改变袖口平面轨迹的视觉避让。无法满足约束时不会使用旧的无约束姿态兜底。允许漏键的生成会通过既有局部松蛇窗口重试接触规划，最多四次修复；仍无解则保留明确失败原因，不会无限循环或发布越界动画。

## 缓存与历史演奏

缠绕上限只影响动作，修改它复用接触规划与 ArcCreate 触点回放。姿态缓存包含上限、舒适速度和 `winding_paths.py` 源码指纹，不能误用旧的无约束动作。相机、流速和音轨变化继续沿各自缓存处理。

历史演奏保存自己的动作；旧演奏不会因升级自动变为受约束的版本。工作台会明确提示旧演奏尚未应用，需要重新生成预览。原视频保留用于比较。

## Dantalion 实测

新演奏 `20261107-145326-d59a03` 复用原 `20261107-130237-6c97d3` 的完整触点、回放、原生判定及游戏画面，仅更新手部运动／场景快照。

开头右手在 **5.3167–5.4833 s**、左手在 **8.5333–8.7167 s** 的地面长按释放间隙执行真实解缠。全曲袖口角度的连续插值认证范围为 **−220.781° 至 +258.412°**，最终回到 0°。全曲增加约 **2.065 m** 的必要绕行；按住的触点没有漂移，原 **1432 命中／44 漏键、9,703,314 分**完全保留。

独立读取保存的 Blender 袖口对象，在全曲 **36,681** 个采样位置检查，得到 **−220.776° 至 +258.406°**；另有 **1001** 个 Blender／WebGL 对齐检查通过。整只手套峰值约 **2.75 m/s**，腕部最高 **360°/s**，符合原设置。证据在演奏目录的 `winding-blender-check.json`、`alignment-check.json`、`metrics.json` 与 `output/arm-winding-qa/`。
