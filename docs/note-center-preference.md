# 音符中心偏好

## 目的与设置

判定区允许偏心落指，但不应让所有音符都常态化贴边。保持软约束：偏心省下的转移、避让、转腕等代价足够大时，仍可选择偏心。

工作台「手部动作」新增：

- **音符中心偏离代价**：默认 50，0 关闭，可输入小数。
- **中心免费偏移半径**：默认 5 mm，可调 0–15 mm。中心附近的小调整不收费。

半径之外按 `max(0, distance_m - free_m)² / 0.020²` 计费，再乘权重。采用平板上的物理距离，不随相机、视频分辨率或帧率改变。

- 地键／天键：在实际触点按下的位置，每个音符只计费一次，与点按持续帧数无关。
- 地面长条：在服务该长条的帧区间按秒积分；同一长条重复 part／计分点不会重复加价。
- 蛇：此项始终为零，只使用已有 `arc_trace_weight`。不会因每个计分点都再收中心代价而破坏锯齿抄近路。

计分仍优先于运动偏好；所有原生判定、按压竞争、颜色绑定、速度与双臂缠绕约束不变。这不是关闭判定区落指，也不会强制每次都落在精确中心。

蛇若仍不愿正常描线，请同时检查描蛇权重。已有加速度惩罚 100 时，旧试验权重 0.5 并不合适；已验证的组合是几何偏离代价 1000、加速度惩罚 100。中心偏好不能替代蛇自身的描线偏好。

## 实现

统一度量位于 `planning/note_center.py`，进入 `_Graph._finish` 的新接触／扩展／伙伴接触增量，同时进入 `contact_placement.py` 的触点精化目标，并加入向音符中心回移的连续候选。不能只在离散候选选完后收费，否则前后两个阶段会相互抵消。

`MultiCost.note_center_deviation` 记录离散搜索分量；与原有设计一致，最终精化后的实际统计另外写到 `plan.json.note_centering` 和演奏元数据，在工作台显示偏心中位数／第 90 百分位。统计使用真实提交给 ArcCreate 和动画的坐标，不用初始候选或手套外观估计。

新增设置和实现哈希进入正常规划缓存键。旧演奏缺少中心权重时按关闭恢复，避免把历史动画说成新偏好结果。新默认值通过 defaults revision 应用到新生成的设置，旧演奏本身不被修改。

地面长条仍可能明显偏心。例如 `hold_point` 会避开会抢占蛇颜色的区域；为了颜色锁正确性和接近的其他音符，触点精化也不能随意把它移回中心。此类运动是明确约束与成本取舍，不是漏掉长条的收费。
