# 交叉深度与手腕反拧代价

## 工作台设置

「手部动作 → 反手与手腕偏好」中提供：

| 参数 | 新默认值 | 含义 |
| --- | ---: | --- |
| 交叉持续代价 | 1 | 左指尖在右指尖右侧、双手同时按住的每秒成本 |
| 交叉深度代价 | 100 | 超出 5 mm 免费量的水平交叉深度，按米·秒计费 |
| 手腕反拧代价 | 10 | 超出舒适偏角的俯仰／偏航偏差平方，按秒计费 |
| 手腕舒适偏角 | 30° | 俯仰和偏航分别应用的免费角度 |

可输入小数。新权重各自设为 0 可关闭。修改后重新生成，旧演奏不会悄悄改变；缺少新参数的历史设置按关闭恢复。默认值为经过验证的起点，不是所有谱面的最优参数。

持续、深度、反拧是不同的可叠加偏好。蛇颜色用手偏好等原有成本仍保留；如果调大后某段仍然反手，可能是其他成本或可达性／计分／解缠约束占优。计分漏键数、红键目标优先级仍在这些软成本之前。±260° 袖口累计缠绕与整只手套速度／转腕速度上限仍由原有流程验证。

## 深度

平板坐标以米计：

```
C_depth = crossing_depth_weight * sum(max(0, x_left-x_right-0.005) * dt)
dt = 1/60 秒
```

只在双手同时按住时积分，与已有持续成本采用相同的接触时域。交叉 50 mm、持续 2 秒，深度积分为 `(0.05-0.005)*2=0.09 米·秒`；默认深度代价为 9。此项直接进入图搜索，触点精化也使用同一公式，避免后续微调撤销规划偏好。

## 反拧角度的定义

目前手套只有俯仰和偏航，没有完整前臂 IK 或解剖意义上的前臂旋前／旋后关节。这里计算的是**相对身体侧自然方向的手套姿态偏差**，不是相对世界坐标零角度。

共享实现位于 `planning/wrist.py`：身体左右侧虚拟手臂锚点为 `(±0.18,-0.38) m`，指尖朝锚点的方向决定自然偏航；在待机点 `(±0.085,-0.068) m` 校准为原有的左右 ±18° 偏航、10° 俯仰。这样把手正常伸向屏幕另一处，不会仅因为世界朝向变了就被算成大幅反拧。偏航差取最短的 ±180° 差值。

```
strain = sum_over_hands_and_axes((max(0, abs(angle-natural_angle)-free_deg)/90)²)
C_wrist = wrist_twist_weight * sum(strain * dt)
```

免费角度对俯仰、偏航分别应用；报告的 `active_peak_deg` 是两轴偏差的向量长度，不是一个硬角度上限。

## 两个阶段

1. **接触规划与精化：静态姿态估计。** 将真实 `HAND_PARTS` 传入规划器，使用其中四个手掌／袖口／指关节身体球代理和有限俯仰／偏航目录，先找间隙最好的静态姿态，再选择反拧最少的一组。坐标按 5 mm 缓存。只评估双手同时贴屏的时间；它不包含腾空、完整指头几何、时间连续性或前臂碰撞，不能宣称与最终手腕角度完全一致。但它确实影响用手选择与落指点，不只是最终手套造型。
2. **实际姿态求解：真实角度成本。** 完整手套姿态搜索使用同一自然方向和反拧公式，以实际时间间隔加入新成本，同时保留原有间隙、桌面、平滑与硬速度约束。之后继续执行袖口解缠；实际反拧统计在最终运动上计算。没有新建手套碰撞失败门，也不会因估计姿态残余重叠直接跳过音符。

图搜索的 `wrist_twist_s`、`crossing_depth` 属于离散搜索成本；`plan.json.crossing_ergonomics` 根据精化后触点重新测量，`metrics.json.wrist_twist` 则记录实际演奏的持指姿态。两个阶段是有界顺序求解，不宣称全局联合最优。增大权重也不保证每个瞬间的峰值角度都下降，因为目标是累计软成本。
