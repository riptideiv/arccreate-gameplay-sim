# 连续加速度代价与平滑描蛇

## 使用

在工作台「蛇的路径与松手」中使用：

- 路径策略：计分优先。
- 优先描蛇的几何形状：开启。
- 偏离中心线的代价：1000。
- 加速度惩罚：100（新默认值，可输入小数；0 关闭）。

这些是两段已验证片段的起点，不是所有谱面的通用最优权重。之前没有连续加速度成本时尝试的描线代价 0.5／1，不应直接作为新组合的推荐值：此时会过分偏好省力，连普通蛇也不愿描线。强制「描线」策略仍要求中心线，无法靠加速度惩罚把它改成抄近路策略。

旧演奏没有新参数时按 0 显示，忠实保留历史配置；播放旧演奏不会悄悄重规划。重新生成才应用新设置。规划缓存自动纳入新参数及实现哈希；原有流速、音频和相机等缓存隔离保持不变。

## 成本与边界

指尖位置使用米，固定采样间隔为 `dt=1/60` 秒：

```
a[i] = (p[i+1] - 2*p[i] + p[i-1]) / dt²
E = sum(dot(a[i],a[i]) / 5² * dt)
C = acceleration_weight * E
```

这不是超过 75 m/s² 才触发的二元惩罚。任何非零加速度都会付出连续代价；旧的腾空阈值保留并在界面明确区分。计分漏键数优先于红键漏键数，之后才比较包括加速度在内的运动偏好。

`trajectory.py` 负责统一计算：

1. 持指内部的真实二阶差分，并为尚未连接的两端暂记静止边界。
2. 新 tick 延长同一接触时，只计算追加部分及跨边界的两个三点组，撤销旧尾端的临时静止代价。
3. 分离接触之间使用带速度回退的五次缓动屏幕 XY 轨迹，接上前一触点末速度及下一触点初速度，替换相应静止边界。不是把每个小段都当作互不相关的静止运动。
4. 接触头部因组合路径变化时，重新结算入场边界。图中保存前一接触的末帧与末两个位置，而非整条历史；状态合并键保留这些信息及当前末两个位置，避免合并不同速度的状态。

这是触点运动模型。腾空抬高、回家等待、手套避让和袖口解缠属于后续三维运动，最终仍使用原有整只手套速度、转腕及解缠校验。这里不宣称 XY 估计就是完整三维加速度。

## 真正平滑的候选

仅给原锯齿和它的缩小版本加惩罚不够。新候选对**整条连通蛇**求解：

```
min ||p - centre||² + (tau*60)^4 ||D²p||²
```

使用自然边界、五对角 Cholesky 分解，时间与空间均为 O(n)，无需新增 SciPy 依赖。尝试 40／80／160／320 ms 的平滑尺度。直线保持直线；快速折返被更强地抑制。整条蛇的平滑结果缓存后按 tick 所属区间切片，避免每个 tick 重置速度。延长接触时保留原前缀，以位置和速度连续的短过渡衔接平滑引导线。

这些只是新增候选，原始中心线、稳定判定区锚点、原有抄近路与重接路径仍保留。所有候选经相同的原生时间窗、颜色归属、触点覆盖和硬速度检查后才进入搜索。最终触点微调也使用相同加速度代价。没有在动画层偷偷平滑触点，ArcCreate 和 WebGL 仍消费同一组实际坐标。
