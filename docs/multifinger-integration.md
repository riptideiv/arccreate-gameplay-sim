# 多指模拟器合并记录

多指实验分支保留较大的平板和双节拇指。合并前使用 ArcCreate 原生判定验证整曲演奏，并核对从曲首到最后一个判定的搜索结果。

## 问题与修复

- GitHub 的 `main` 停在公开快照。本地 `main` 已包含工作台队列和 Rust 搜索的合并。草稿 PR 包含这段历史及其后续的模拟器更新。
- Rust 搜索目前只在每只手保存一个指尖状态。开启多指后选择了 Python 后端。Rust 版本需要在搜索、去重、续搜和回放验证中保留每根手指的状态。
- 带交叉约束的搜索有一条最终补救路径，可能在中途取出可用前缀并把剩余项目全部记为漏键。整曲验证必须区分这条路径与逐项目尝试后的漏键。

- 用 Cargo 直接编译 macOS 扩展时，Python 符号需要在加载时解析。开发验证用 `cargo rustc` 加上 `-C link-arg=-undefined -C link-arg=dynamic_lookup`；常规安装仍使用项目的 Maturin 构建。
- 测试工作区的默认 Blender 位置没有可执行文件。整曲任务通过本机 `BLENDER_BIN` 选择已安装的 Blender，机器路径没有写入仓库。
- 四指片段的接触与 Python 参考结果一致。原生搜索在每只手保留两根指尖，分别跟踪连打历史，并验证同手跨度、按住时的换指和对手触点。最终路径逐步由 Python 参考规则复核。

- 整曲中的短拇指可达范围比原有的通用多指跨度更窄。规划器现在使用手模能在玻璃上触到的最短和最长跨度；只有拇指按住时，自由食指沿可达范围内的曲线过渡，避免两端可达而中间不可达。
