## 修改与正确性边界

- `GameplayProjection` 固定相机矩阵只建一次，算术、有限值／相机后方检查及公开 API 不变。
- `Regions` 以保留的几何身份和精确有效夹取时间缓存多边形，限定在同一投影／区域设置实例。不同源段的拆分计分点不会只因父 ID 相同而冲突。内部不可变，调用方得到新可变列表，每实例上限 65,536 条。
- `_Graph._scoring_extensions` 按 `(old touch ID, candidate ID)` 缓存有序完整物理分支，包括不可行结果。原生宽限与覆盖只对每物理分支算一次；`_finish` 仍对**每个 DP 状态**执行，保留另一只手、颜色归属／释放锁、连打历史、交叉与耦合代价。
- 前缀速度使用分支原有的精确容差；新延伸检查尾段和边界边。覆盖仍查完整路径，因为新计分点可能在更早前缀被接住，既有绑定／描线摘要不变。
- 长历史仍用不可变 tuple 和 O(1) 随机访问。更复杂的持久化前缀暂缓：小缓存优化后相关开销已小，而早期帧的颜色／计分检查使重写风险较高。没有减少候选或搜索质量。
- `plan_cache.py` 键含谱面字节／路径、设备、窗口、全部规划源码／版本、参数、排除和避让区间。已知展示／姿态／导出字段排除，未知字段保守保留。完整搜索后结构校验、摘要、fsync＋原子替换发布；失败／取消不发布半成品，损坏／不兼容回退正常搜索。

CLI／工作台默认 `output/contact-plans/`；`--no-plan-cache` 关闭，`--plan-cache-dir` 隔离。库 `create_plan()` 默认 `cache_dir=None`，基准与旧测试保持不缓存。命中通过现有进度流发 `cache_hit=true`。场景、姿态、原生画面仍各自失效。

## 剖析与验证

独立 cProfile 的 20–30 s 调用数，仅解释原因，不作主计时：

| 工作 | 基线 | 优化 |
| --- | ---: | ---: |
| 相机矩阵构建 | 627,783 | 2 |
| 实际判定多边形 | 122,980 | 559 |
| 原生路径守卫 | 109,602 | 14,690 |
| 触点驻留／去重 | 91,931 | 13,914 |
| 耦合 `_finish` | 243,201 | 243,201 |

优化剖析约 24 秒、基线 45.5 秒；无剖析中位数约 10.3／21.2 秒。剩余瓶颈为 DP 状态／候选迭代、耦合校验与代价；蛇路径准备、原生判定与解析占比相对上升。`future`、`bound_frames` 与去重占比较小，暂不重写历史表示。

**18 次主试验完整规划只去掉 `stats.elapsed_s` 后全部一致**，包括触点时刻、手分配、采样路径、漏键、计分台账、全部代价和访问／剪枝状态数。剖析与缓存命中结果也一致，无观察到的平局选择或得分／动作代价变化，因此无需重渲染相同触点的原生回放。

该优化版本 **150 项 Python 测试通过**。新增覆盖投影等价、源／时间／投影隔离、可变副本、负结果复用、前缀容差／边界检查、更早前缀接取、缓存损坏、设备／谱面／窗口／设置／源码失效、展示字段复用与取消不发布。原计分窗口、相机包络、颜色锁／宽限、局部接取、描线／尾端偏好及进度测试不变。后续版本测试数量见相应验证记录。
